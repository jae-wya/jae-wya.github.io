The system

Built for people who don't use software.

The people working inside this system are florists, riders, and cashiers — not software users. That one constraint drove every technical decision. If a screen needed explaining, it was wrong.

Authentication

A login staff would actually use

Staff share terminals and work with wet hands. Email-and-password sign-in would have been abandoned inside a week, so I built passwordless access instead — a short code, hashed and session-backed. Simple to use, not simple underneath.

Data intake

Paste the message, don't retype it

Orders arrive as free-form chat mixing Tagalog and English, often skipping fields. The parser pulls recipient, address, delivery window, card message, and pricing, then reports what's missing. Encoding became a review step instead of a re-entry step.

Storage

Photos that survive a restart

The host wipes local files on every restart — the first version silently lost uploads. I moved every photo to object storage, making them permanent and reachable from a rider's phone in the field.

Performance

Scaled before the volume arrived

Reads are cached, but any write clears the cache — so navigation feels instant while your own edits still appear immediately. The failure mode that makes internal tools feel broken is seeing stale data right after you changed something. Order history is paginated and indexed on the columns that actually get filtered, built before the volume demanded it.

Fulfilment

A printable waybill per order

Each order generates an A5 sheet carrying the arrangement spec, delivery window, recipient details, and a QR the rider scans on arrival. Riders kept reporting blank QR codes on printed sheets — the cause turned out to be browsers dropping embedded images at print time, invisible on screen and only ever visible in the field.

Visibility

Answers without reconciliation

Management compares branches side by side on volume, revenue, average order value, cancellations, and waste. A restock forecast projects stockouts fourteen days out. None of this existed before without an hour of manual work.

The finding that mattered more than the returns

Because the system captures every order regardless of how it arrives, I could reconcile first-party order records against what Ads Manager reported as conversions.

0

The majority of orders never registered as conversions. They closed through Messenger conversations, GCash transfers, and walk-in visits — no pixel event fired anywhere in those paths.

Campaigns that looked like underperformers in the dashboard were, by actual revenue, likely among the strongest. Budget was being allocated against a systematically incomplete picture. Having the order data in a queryable database is the only reason the gap was visible at all — an ad platform cannot report on conversions it never sees.
